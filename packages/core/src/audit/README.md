# Matthew delivery interface

The modules now live in the SR-1 workspace. The public scan service expects a `ScanStore`; its `enqueue` call maps to the shared `scan_domain` job. The public MCP `get_readiness_score` and `/api/score` should call the same `ScanService.request` method. The worker calls `complete` and persists the complete result. `PrivateSupplement` is deliberately applied only after the cached public result is read.

The paid flow requires a verified TXT challenge, the business agent's authority attestation, acceptance of the versioned terms, and vault intake before a test login can be used. A production rollout needs legal review of attribution and authority under [15 U.S.C. § 7001(h)](https://uscode.house.gov/us/usc/119-118/t15/s7001/). The credential vault must encrypt credentials and return only a reference; prompts, MCP arguments, reports, and logs must never contain credentials. Gated browsing belongs in a controlled, read-only auditor browser with form submissions disabled; the Apify adapter is for public pages only.

`AuditPipeline.buildAndDeliver` supplies the same initial assets to both offers. The caller is responsible for persisting reports and events, moving the paid order to delivered, and issuing the transactional delivery email through the shared interfaces. The `deliver` callback must be idempotent by order ID. The MT-6 public crawl claims one `audit_crawls` row per paid order before starting Apify. Its ad-hoc webhook includes `x-outrun-apify-secret`; the route authenticates the header, records one event per run outcome, and enqueues `handle_apify_event`. The worker wakes the auditor after the dataset is ready. An uncertain run start keeps its claim so a retry cannot launch a second paid crawl automatically.

The Next app mounts `/api/score`, `/score/[domain]`, the landing page, Markdown alternates, the signed-in dashboard shell, and the Apify webhook. With `DATABASE_URL` and a stable `AUTH_SECRET` or `CREW_TOKEN_SECRET`, `apps/web/lib/scan-service.ts` uses Postgres for completed scans and rate-limit events and pg-boss for the `scan_domain` job. The worker handles that job. Without a database, process memory is used only in local development; production returns 503. The MT-6 audit saves evidence-backed findings in `reports` and enqueues `build_kit`; asset generation, report delivery, and Checkout still belong to later cards. The dashboard renderer reads event and session views supplied by the shared database. No live paid-access testing should start before legal review.
