# Matthew delivery interface

The modules now live in the SR-1 workspace. The public scan service expects a `ScanStore`; its `enqueue` call maps to the shared `scan_domain` job. The public MCP `get_readiness_score` and `/api/score` should call the same `ScanService.request` method. The worker calls `complete` and persists the complete result. `PrivateSupplement` is deliberately applied only after the cached public result is read.

The paid flow requires a verified TXT challenge, the business agent's authority attestation, acceptance of the versioned terms, and vault intake before a test login can be used. A production rollout needs legal review of attribution and authority under [15 U.S.C. § 7001(h)](https://uscode.house.gov/us/usc/119-118/t15/s7001/). The credential vault must encrypt credentials and return only a reference; prompts, MCP arguments, reports, and logs must never contain credentials. Gated browsing belongs in a controlled, read-only auditor browser with form submissions disabled; the Apify adapter is for public pages only.

`save_audit` persists cited findings, `build_kit` generates the same initial assets for both paid offers, and `deliver_report` sends an idempotent transactional email before marking the order delivered. `AuditPipeline.buildAndDeliver` remains a fixture for the shared asset contract. The MT-6 public crawl claims one `audit_crawls` row per paid order before starting Apify. Its ad-hoc webhook includes `x-outrun-apify-secret`; the route authenticates the header, records one event per run outcome, and enqueues `handle_apify_event`. The worker wakes the auditor after the dataset is ready. An uncertain run start keeps its claim so a retry cannot launch a second paid crawl automatically.

The Next app mounts `/api/score`, `/score/[domain]`, the landing page, Markdown alternates, the signed-in dashboard shell, and the Apify webhook. With `DATABASE_URL` and a stable `AUTH_SECRET` or `CREW_TOKEN_SECRET`, `apps/web/lib/scan-service.ts` uses Postgres for completed scans and rate-limit events and pg-boss for the `scan_domain` job. The worker handles that job. Without a database, process memory is used only in local development; production returns 503. The paid audit saves evidence-backed findings in `reports`, enqueues `build_kit`, and serves delivered reports and assets through private, noindex routes. Checkout still belongs to Srikanth's order work. The dashboard renderer reads event and session views supplied by the shared database. No live paid-access testing should start before legal review.
