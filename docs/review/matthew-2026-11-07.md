# Review: scan and delivery modules (commit 07e7682)

Reviewer: Srikanth, with Claude Code. Date: 2026-11-07.

## Fixed in this PR
- **`safeFetch` failed on every real request.** Since Node 20, Node calls `lookup` with `{ all: true }` and expects an array back. Our version returned one address, so every fetch to a hostname failed with `ERR_INVALID_IP_ADDRESS`. `probe()` swallowed that error, so every scan came back `unknown`. The fix answers both call forms. A new test drives the real request path against a local server, through a loopback override that only tests can use.
- **The scanner could freeze the server.** The CTA regex took quadratic time: 325 KB of `<a>xxxxxxxxxx` ran for 8.9 s, and the 2 MB cap allowed about 6 minutes. Every regex now sees at most 256 KB, and the tag and inner-text scans are linear and bounded. On a hostile 2 MB page the scan now finishes in milliseconds, and a test enforces this.
- **A caller's abort signal dropped the deadline.** When a caller passed its own `signal`, the 10 s total timeout was lost. The timeout is now combined with the caller's signal through `AbortSignal.any`.
- **CI.** Matthew has since moved the code into `packages/core` (MT-3, #8) and the tests run under vitest, so the fixes were re-applied there and the three new tests live in `packages/core/src/matthew.test.ts`.
- **Gated products in the auditor skill.** That section of `naive/skills/auditor.md` is removed in PR #10, because no tool backs it.

## Still open, in priority order

### 1. Wiring (partly done by MT-3)
MT-3 (#8) moved the files into `packages/core` and mounted the free scan. Re-check this list against main:
- Nothing imports it.
- Root `tsconfig.json` doesn't include `src/`, `integrations/` or `tests/`. Compiled with the repo's strict settings, these files have 25 errors, starting with TS5097 on the `.ts` import extensions.
- There are no routes for `/api/score`, `/score/[domain]`, `/report/[token]`, `/dashboard` or `/api/webhooks/apify`.
- The `scan_domain`, `handle_apify_event`, `build_kit` and `deliver_report` jobs are still stubs.
- The crew tools `scan_domain`, `start_crawl`, `get_crawl_pages` and `save_audit` don't exist.

**Fix:** move each file to the path in the table at the end, drop the `.ts` extensions, and port the tests to vitest next to each module.

### 2. Scan types don't match the frozen contracts
- `packages/core/contracts/domain.ts` defines `ScanCheck` as `passed`/`title` with tiers `critical | important | nice`, and `CheckId` requires snake_case.
- `src/scan/contracts.ts` defines its own shape (`status`/`label`/`category`) with hyphenated ids such as `ssr-answer`. Every id fails `CheckId`, so findings that cite a check fail `save_audit` and `check_draft`.
- `ScoreResponse` (`contracts/api.ts`) needs `{domain, score, checks, reportUrl (absolute), cachedAt}`. The code returns two scores, a relative `reportUrl`, and `scannedAt`/`cachedUntil`.
- It should implement `ScanDomainFn`/`ScanResult` from `packages/core/src/integrations/types.ts`.
- Weights belong in `constants.ts`.
- The six marketing checks aren't in the plan. Adding them needs a contracts PR that all three approve.

### 3. Building a Kit always fails on the shared fakes
- `src/audit/pipeline.ts:57` requires exactly 50 prospects and calls `discover(domain, 50)`.
- Core's `DiscoverFn` is `({limit, icp})`, and its fake returns 2 companies, so `build_kit` always throws on fakes and in `e2e:loop`.
- **Fix:** use `Integrations.discover`, accept a shortfall and record it as an event.

### 4. Apify runs never call back
- `integrations/apify.ts:16` starts the run with no ad-hoc `webhooks`, so the auditor is never woken.
- There's no idempotency key, so a job retry pays for a second crawl.
- There's no `timeout` or `memory` cap.
- **Fix:** implement core's `ApifyClient` (`types.ts`: `actorId, input, webhookUrl, idempotencyKey`, returning `datasetId`, paged with `{offset, limit}`) in `packages/core/src/integrations/apify.ts`. Wire it to `FakeApify`.

### 5. Webhook dedupe lives in memory
- `pipeline.ts:41` keeps seen runs in a `Set`, which is lost on restart and with more than one instance.
- It marks a run as seen before the work is enqueued, so a failed enqueue drops Apify's retry.
- **Fix:** use `recordWebhookOnce(db, "apify", runId)` in the same transaction as `enqueue("handle_apify_event")`. The Naive webhook does exactly this in PR #11.

### 6. Apify header check
- The early length check reveals the secret's length.
- There's no support for a rotated secret.
- It doesn't re-fetch `actor-runs/{id}` before trusting the payload.
- **Fix:** move it next to `verifyNaiveSignature` in `packages/core/src/webhooks/verify.ts`, compare SHA-256 digests, and accept a list of secrets.

### 7. Score rate limit can be bypassed
- `src/scan/service.ts:26`: the check and the record are separate awaits, so concurrent requests all pass.
- The salt defaults to `'local-development'`.
- `retryAfter` is fixed at 3600.
- It doesn't count `scan.requested` events, as MT-3 asks.
- It uses magic numbers instead of `SCORE_RATE_LIMIT_PER_HOUR`.
- `src/scan/mcp.ts` takes `requesterIp` and `privateSupplement` as tool input, so a caller can set both. The contract in `contracts/mcp.ts` takes only `{domain}`.
- **Fix:** count hashed-IP `scan.requested` events in one SQL statement, take the salt from a secret, and derive the IP on the server.

### 8. Error shape
- `src/scan/http.ts:14` returns `{error: 'rate_limited'}` and `{error: 'invalid_domain'}`, while the contract is `ErrorBody`. `invalid_domain` isn't an `ErrorCode`.
- The catch-all turns database errors into 400s.
- **Fix:** throw `AppError` and render with `toBody(requestId)`.

### 9. Domain proof isn't tied to the order
- `src/audit/access.ts:12` verifies whatever domain the caller passes for an order. Someone who owns `attacker.com` can unlock gated access on an order for `victim.com`.
- The state is in memory and never expires.
- The feature isn't on any MT card, and its own README says it needs legal review.
- **Fix:** defer it. If it stays, read the domain from the `orders` row.

### 10. Dashboard sign-in
- `src/dashboard/views.ts:5` takes a `signedIn` boolean. A caller passing `!!session` shows the dashboard to any GitHub user.
- There's no 403 path.
- The allowlist matches email, while `AUTH_GITHUB_ALLOWLIST` is GitHub logins.
- **Fix:** enforce the allowlist in the Auth.js `signIn` callback and in middleware for `/dashboard/**`.

### 11. Dashboard data
- `LedgerEvent.at` should be core's `ts`.
- `slice(-50).reverse()` assumes oldest-first order, but `eventsFor` is newest-first.
- The counted event types (`candidate.discovered`, `scan.completed`, `order.paid`, `report.delivered`) aren't defined anywhere yet.
- Cost per audit adds up every cost.
- The page reloads in full every 2 s.

### 12. Duplicated prices and limits
- `PRODUCTS`, `CACHE_TTL_MS`, `AUDIT_MAX_PAGES` and the fetch limits duplicate `constants.ts`, and the product labels already differ.
- `/checkout?package=` links don't exist.
- The landing form posts to `/score?domain=`, but the route is `/score/[domain]`.
- No page has the markdown alternate link that MT-3 and MT-5 require.

### 13. Kit validation
- Every line of the Kit must carry a `[findingId]`, so the `llms.txt` and emails the customer publishes are full of `[f1]` markers.
- Kit costs are never emitted as events.
- It injects `deps.llm` instead of core's `llm()`.
- **Fix:** keep citations in a separate `claims[]` field that the validator checks.

### 14. SSRF range gaps (`safeFetch`)
- `/^[23][0-9a-f]/` lets `200::1` and `3fff::/20` through. Use `(first16 & 0xe000) === 0x2000`.
- `192.88.99.0/24` isn't blocked.
- An https→http downgrade on redirect is allowed.
- One abort listener is added per hop and never removed.

### 15. Report tokens
- The 256-bit token can't be guessed, but `getByToken` scans every report in memory.
- **Fix:** store a hash in `reports.access_token` and look it up through the unique index. Add `Referrer-Policy: no-referrer` and `X-Robots-Tag: noindex`.

### 16. Untrusted text and links
- `validateFindings` accepts any http(s) URL. Restrict it to the customer's domain or the crawled pages.
- `fullScan` follows call-to-action links to other domains.
- Apify page text reaches agents without `untrusted()` and `scrubDeep`.
